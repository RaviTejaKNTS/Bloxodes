# Bloxodes Traffic Diversification and Community Plan

Created: 2026-07-06

## Why this exists

Bloxodes has too much business risk concentrated in one search engine and one page family. The Roblox Music IDs page has been a major traffic source, and the recent Bing indexing issue showed that a single crawler decision, moderation failure, technical rule, or page-quality signal can hurt the whole site.

The goal is not to abandon search. Search is still one of the best channels for Bloxodes. The goal is to make the site resilient enough that one page or one search engine cannot define the entire business.

## Current risk

- Too much traffic depends on Bing.
- Too much traffic depends on the Roblox Music IDs page.
- Community and direct-return channels are still early.
- Apps are not yet acting as a retention layer.
- Social distribution is not yet broad enough.
- More page families need to become real traffic contributors.
- Bot/security changes can accidentally affect crawlers, agentic tools, and people citing the site if not tested carefully.

## Target outcome

- No single page should carry more than 35% of total traffic.
- No single search engine should carry more than 50% of total traffic.
- At least five page families should contribute meaningful traffic.
- Discord, app users, social followers, direct visitors, and email or push subscribers should become real return channels.
- Security and bot rules should protect the site without harming Googlebot, Bingbot, ChatGPT, other legitimate AI crawlers, or normal curl-style fetches that cite Bloxodes as a source.
- Content growth should make Bloxodes feel like a Roblox companion network, not just a collection of SEO pages.

## Positioning

Bloxodes should become a practical Roblox companion site:

- find IDs, codes, tools, stats, wiki pages, checklists, quizzes, and events;
- save useful Roblox resources;
- get notified when something changes;
- request missing pages and tools;
- report expired codes, broken IDs, and stale game info;
- participate in a moderated, safe Roblox research community.

The unique angle should be utility plus community signals. Bloxodes should not only publish pages. It should let players help keep the site alive, accurate, and useful.

## Channel strategy

### Search

Search remains the foundation, but it should be spread across more surfaces.

Priority page families:

- music IDs and related music tools;
- codes pages;
- wiki hubs;
- wiki collection pages;
- calculators and planners;
- checklists;
- quizzes;
- events pages;
- stats pages;
- Roblox platform troubleshooting articles;
- game-specific how-to articles;
- curated catalog pages.

Important rule: new pages should not be thin just to increase count. Each page family needs a clear reader job, source-backed data, metadata, internal links, sitemap coverage, and page-contract tests before becoming a major production surface.

### Discord

Discord should become the main community home.

Recommended community concept:

```text
Bloxodes Field Desk
Roblox codes, IDs, tools, wiki requests, and live game intel.
```

Core channels:

- announcements;
- new codes and IDs;
- report expired codes;
- request music IDs;
- request tools;
- request wiki pages;
- Roblox game discoveries;
- help and questions;
- polls and votes;
- changelog;
- mod log or public safety notices.

Useful community loops:

- users report a missing code or music ID;
- moderators verify it;
- the site updates;
- the Discord post links back to the page;
- the app sends a notification;
- social snippets promote the update;
- more users join the reporting loop.

Safety requirements:

- no dating, roleplay, adult, or find-friends positioning;
- no DM-first culture;
- clear public rules;
- AutoMod enabled;
- slowmode in high-risk channels;
- moderation queue for user submissions that can reach the site;
- no user-generated content should become crawlable site HTML without moderation.

### Mobile apps

The app should not be a website wrapper. It should be a Bloxodes companion.

Android should probably launch first because Roblox discovery communities often move faster there and the store process is usually simpler. iOS should follow once the app value is proven.

Core app features:

- saved games;
- saved music IDs;
- copied music ID history;
- code alerts;
- music ID alerts;
- game watchlist;
- recently viewed pages;
- calculators and tools;
- stats shortcuts;
- local progress for checklists and quizzes;
- optional account sync;
- push notifications for followed games and page families.

The app should create return behavior. It should not depend only on app-store search.

### X

X should be used for credibility, indexing discovery, fast updates, and public changelog energy.

Useful formats:

- new page announcements;
- code update posts;
- music ID discovery posts;
- tool launches;
- game stat snapshots;
- short explainers;
- Bing or Google recovery progress updates when relevant;
- community polls.

X should not be the only social channel because the Roblox audience is fragmented.

### Short-form video

Test YouTube Shorts, TikTok, and Instagram Reels with reusable formats.

Repeatable formats:

- "3 working Roblox music IDs";
- "new codes for this game";
- "one tool that saves time in this Roblox game";
- "fast Roblox setting fix";
- "game stat of the day";
- "what changed in this Roblox update";
- "Bloxodes community found this".

Each short should point to a specific page, Discord channel, or app action.

### Reddit and Roblox-adjacent communities

Use carefully. The goal is to be helpful, not spammy.

Rules:

- answer real questions;
- cite Bloxodes only when it genuinely helps;
- do not mass-post links;
- build reputation through useful comments;
- avoid communities where promotion is not allowed;
- keep posts specific to the game or problem.

## Content expansion priorities

### Wiki hubs

Wiki hubs should become durable evergreen pages for major Roblox games.

Good wiki hubs include:

- game overview;
- core loop;
- controls;
- currencies;
- progression;
- beginner tips;
- related Bloxodes tools;
- related checklists;
- related collection pages;
- codes page when available.

### Wiki collection pages

Collections can diversify search because they target durable in-game systems, not only current codes.

Good collection examples:

- pets;
- fruits;
- crops;
- weapons;
- classes;
- units;
- abilities;
- maps;
- bosses;
- items;
- upgrades.

Requirement: do not create collection pages unless there is source-backed item data and enough useful fields to make the page worth indexing.

### Tools

Tools create return visits and app value.

Good tool categories:

- calculators;
- converters;
- planners;
- trackers;
- timers;
- value estimators;
- progress estimators;
- item comparison tools;
- Roblox platform troubleshooting helpers.

Tools should be internally linked from wiki hubs, articles, and app screens.

### Checklists

Checklists are good for repeat use and app retention.

Useful checklist types:

- beginner progression;
- event completion;
- item collection;
- weekly tasks;
- update preparation;
- raid or boss preparation.

### Quizzes

Quizzes can help social sharing, but they should stay accurate and safe.

Useful quiz types:

- game knowledge;
- item recognition;
- beginner versus expert;
- update knowledge;
- music or catalog quizzes where appropriate.

### Articles

Articles should fill specific search and social jobs.

Priority article categories:

- Roblox platform troubleshooting;
- how-to guides;
- update explainers;
- game-specific practical guides;
- comparison guides;
- beginner guides;
- safety and settings guides.

Avoid weak generic articles that do not add value beyond existing pages.

## Product loops

### Report loop

Users should be able to report:

- expired codes;
- broken music IDs;
- missing Roblox games;
- stale wiki data;
- missing tools;
- unsafe comments;
- inaccurate stats.

Reports should go to a moderation or review queue, not directly to public pages.

### Request loop

Users should be able to request:

- a new codes page;
- a music ID;
- a wiki hub;
- a collection page;
- a calculator;
- a checklist;
- a quiz.

Request volume can guide what Bloxodes builds next.

### Watchlist loop

Users should follow games, pages, or topics.

Watchlist events:

- new code added;
- code expired;
- new tool added;
- new wiki page added;
- event page updated;
- stats changed;
- music ID list updated.

## Guardrails

### SEO and crawler safety

Every major Cloudflare/security change should test:

- normal browser user agent;
- Googlebot;
- Bingbot;
- ChatGPT-User;
- GPTBot;
- OAI-SearchBot;
- ClaudeBot;
- PerplexityBot;
- normal curl;
- scanner user agents such as `masscan`, `zgrab`, `sqlmap`, and empty user agent.

Good bots and useful fetchers should not be blocked from public pages. Scanner and exploit traffic should stay blocked.

### User-generated content safety

No user-generated content should be rendered into crawlable public HTML unless it passes strong moderation.

Rules:

- moderation should fail closed;
- rejected content should never appear in SSR HTML;
- unsafe comments should be removable sitewide;
- moderation failures should alert;
- high-risk terms should be audited regularly;
- pages with user comments should be included in SEO quality checks.

### Page-quality safety

Before launching a new page family:

- verify metadata;
- verify canonical;
- verify robots policy;
- verify JSON-LD;
- verify sitemap coverage;
- verify internal links;
- verify date logic;
- verify mobile rendering;
- verify production fetch as browser, Googlebot, Bingbot, and curl.

## 30-day plan

Focus: stabilize and reduce immediate concentration risk.

- Finish the stability and SEO test plan.
- Add weekly traffic concentration reporting.
- Add weekly page-family reporting.
- Audit Cloudflare bot rules after every change.
- Harden comment moderation and cleanup workflows.
- Launch Discord structure privately or softly.
- Publish the first set of community rules and moderation rules.
- Pick 10 to 20 high-confidence content expansions outside Music IDs.
- Prepare Android app launch checklist.
- Create social templates for codes, tools, wiki, and stats updates.

## 60-day plan

Focus: build return channels and publish more durable page families.

- Publicly launch Discord.
- Add report and request loops.
- Build a review queue for user reports and requests.
- Publish more wiki hubs and collection pages.
- Publish more tools connected to existing traffic pages.
- Add app watchlist and saved items if not already complete.
- Start Android release process.
- Post short-form content consistently.
- Track Discord and app referral behavior.

## 90-day plan

Focus: make Bloxodes less fragile.

- Launch or prepare iOS depending on Android results.
- Add push notifications for followed games or pages.
- Make the top page share trend down toward 35% or less.
- Make Bing share trend down toward 50% or less.
- Grow at least three non-search return channels.
- Build a repeatable content engine for wiki, tools, checklists, quizzes, and articles.
- Add dashboards for content quality, indexing, traffic dependency, crawler access, and community reports.

## First implementation sequence

1. Create the tracking dashboard for traffic concentration.
2. Create a weekly report for page family traffic and search source split.
3. Finalize the Discord structure and moderation rules.
4. Launch Discord softly with a small set of trusted users.
5. Add request and report forms or channels.
6. Pick the first content expansion batch from existing high-intent games.
7. Create social templates for each update type.
8. Turn app planning into a release checklist.
9. Add crawler-access checks to the SEO test suite.
10. Review progress weekly and shift effort toward channels that prove retention.

## Open questions

- Which analytics source should become the source of truth for weekly traffic concentration reporting?
- Should Discord submissions enter the site through a database-backed moderation queue or start as manual mod channels?
- Should Android ship before all app features are ready, or wait for watchlists and push notifications?
- Which page families already have enough strong data to scale fastest without creating thin pages?
- Which social channel shows the best early Roblox audience fit for Bloxodes?

## Success definition

This plan is working when a search drop on one page hurts, but does not threaten the whole site.

Bloxodes should still care deeply about Music IDs and Bing recovery, but the business should also have a growing Discord, app users, social reach, direct visitors, and many durable content surfaces that can survive crawler volatility.
