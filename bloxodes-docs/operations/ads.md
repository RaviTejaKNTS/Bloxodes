# Ads

Last verified: 2026-10-23 against code. Recheck live placement after the next ad layout release.

Bloxodes runs full Mediavine ads. It moved from Mediavine Journey when Mediavine set its ads live on 2026-10-08. The Mediavine site ID is `75d9ab7d-268c-4e03-bb6c-180ca4b8d5ed`.

- **Ad script:** `PublicSiteProviders` loads `https://scripts.mediavine.com/tags/<site-id>.js` in production builds only, with `next/script` `strategy="afterInteractive"` (behind the marketing consent gate when local consent is on). Mediavine places every ad from that one script. Mediavine's custom-site guide asks hydrated sites to run the wrapper after the page has rendered; an earlier start let it edit `#article-body` before React hydrated, which caused React #418 and `removeChild` errors.
- **Script policy:** the public-pages CSP `script-src` allows `'unsafe-eval' 'wasm-unsafe-eval'` because Amazon's bidder script needs `eval`. Secure paths (`/api`, `/auth`, `/login`, `/account`, `/admin`) keep the strict policy. Both live in `apps/web/src/config/csp-directives.json`.
- **ads.txt:** `/ads.txt` returns a 301 redirect to `https://adstxt.mediavine.com/sites/<site-id>/ads.txt`, so Mediavine keeps the file current. Don't add a static `apps/web/public/ads.txt`; it goes stale. Cloudflare caches `/ads.txt`, so purge that URL after any change to its handling.
- **Mixed content:** the CSP in `apps/web/src/config/csp-directives.json` sends `block-all-mixed-content`, following Mediavine's "Force All Ads Secure" guide. Don't add `upgrade-insecure-requests`; it stops Mediavine's directive from applying.
- **Sidebar width:** Mediavine needs the right content sidebar to be at least 300px wide at every viewport of 1200px and up. `.content-sidebar-grid` (in `apps/web/src/app/globals.css`) gives the rail a fixed `21rem` (336px) from 1200px and `3fr / 1.25fr` from 1024px. Site navigation is the top bar, with no left sidebar, so the main column takes the rest. New page templates with a right sidebar must use the same grid.
- **Sidebar ads:** Mediavine adds sticky sidebar ads at the end of the first `aside.space-y-4` on the page. Every content template renders its rail with `PageSidebar` (`aside#sidebar.space-y-4`) inside `.content-sidebar-grid`, once per page, so the rail stretches to the content height. Nothing inside page content may use `aside.space-y-4`. Rail content stays short (ending about 900 to 1,100px from the top at 1440x900). Pages without a rail: the home page, `/wiki`, the `/stats/games` and `/stats/items` rankings, the `/codes`, `/articles` (including `/articles/games/*`), `/events`, `/quizzes` and `/puzzles` indexes, puzzle pages. Tool indexes and every tool and map page keep a rail. Map rails hold sharing and at most three related-map links, so the first sidebar ad sits beside the map.
- **Home page:** the hero, the today strip and the "Pick up where you left off" row sit above `#article-body`, so no ad lands between them. The pick-up row renders only after hydration, which is why it stays outside. Its data comes from `RecentVisitTracker` (mounted in `SiteShell`), which keeps the last 12 content pages a visitor opened in the `localStorage` key `bloxodes:recent-pages`; nothing is sent to a server. Every block below is its own direct child of `#article-body`. From 1280px, `.home-stream` (in `apps/web/src/styles/ads-hubs.css`) puts some blocks in pairs on a 12-column grid with dense flow. An ad Mediavine inserts between the two blocks of a pair spans the full width, and the second block moves back up beside the first, so the ad lands below the pair. Below 1280px the blocks stack and ads can fall between them. A block whose partner has no content takes the full row, so dense flow never pulls a later block into the gap.
- **In-content ads:** Mediavine scans the direct children of `#article-body`, one per page. Sectioned card grids use row groups, long tables are split into chunks, and client interactions never change the direct children. See `.agents/skills/shared/release-and-review/bloxodes-simplify-journey-dom/SKILL.md` for the flat DOM contract. Family layout CSS lives in `apps/web/src/styles/ads-*.css`.
- **Interactive maps:** the map sits in the main column of `.content-sidebar-grid` beside the rail, inside `MapViewport` (`apps/web/src/components/maps/`): a 420px frame up to 800px wide, 600px above. Full screen is a button the reader chooses; it uses a native modal dialog and keeps the map mounted, so pins, filters and progress survive. The map engine stays outside `#article-body`; the guide copy below it is the `#article-body` stream. Never let an embedded map take over the viewport or cover the site shell.
- **Tools:** `ToolPageLayout` gives the rail; shared calculators use `DedicatedToolPage`. Inside `#article-body`: the intro paragraphs, then the live tool in one stable `<div className="ads-tools-widget">`, then how-to, description and FAQ. Tool state changes only what's inside that wrapper. Results grow naturally: no fixed height or inner scroll box.
- **No URL writes on interactions:** GA4 counts every `history.replaceState` or `pushState` as a pageview, and Mediavine takes pageviews from GA4. Pin clicks, tool lookups, resets, keystrokes and same-page jumps must not change the URL. Read deep-link parameters (`?point=`, `?username=`) on load, and build Share links separately without touching the address bar. Real navigation, including a submitted catalog search, stays as it is.
- **Privacy:** `/privacy-policy` contains Mediavine's "Mediavine Programmatic Advertising (Ver 1.1)" block word for word. The dashboard Privacy Policy Health Check looks for that heading and version, and for a link to the policy from the home page (the footer has one). Mediavine adds its US opt-out link in the site footer (dashboard: Settings > Privacy > Privacy Notice Location = Footer) and runs its own consent tool for EU and UK visitors.
- **Cloudflare:** keep Rocket Loader and script deferral off for the ad script.
- **Testing ads:** open the page in an incognito window and add `?test=houseads` to the URL. Mediavine then shows house ads in every slot, so you can check placement without waiting for real fill. Real fill is patchy for the first couple of weeks after launch. `scripts/ads/audit-ad-slots.ts` does the same for a list of pages and reports ad counts, gaps, tall blocks and split card rows (usage in the DOM skill).
- **Dashboard:** revenue updates daily around 10am US Eastern; sessions and pageviews lag two days. GA4 is linked in the Mediavine dashboard and must report in Eastern Time.
