## Search Indexing

- Sitemaps and feed are generated by Next routes from production data and local datasets.
- The local GTA V interactive map route is a static evergreen map entry in `/sitemaps/gta.xml` when the GTA V wiki is published. `/api/search/all` adds one GTA-scoped map result for matching queries; GTA wiki/collection revalidation also expires the map path. The map is excluded from `/feed.xml` because it is an evergreen utility, not a dated article or checklist publication.
- Google Indexing is owner-disabled. The scheduled no-op invocation is removed from the repair manifest; existing submission state is retained. IndexNow is also explicitly disabled. Neither integration is activated by pipeline maintenance.
- The Google job requires both `--apply` and `GOOGLE_INDEXING_API_ENABLED=true` before network submissions.
- Indexing credentials are isolated in `.envs/pipelines/indexing.env`; the service-account JSON is under `.envs/secrets/`.
- IndexNow bootstrap has its own value-free example; keep the public key file/location contract in sync with the site.

## Google index policy

Google can fetch our pages, but since October 2025 it has indexed only the homepage. Search Console URL Inspection confirmed the diagnosis on 2026-10-12. We give Google an allowlist of our strongest page groups and ask it to skip the rest. Bing and other engines keep their existing robots directives.

- The allowlist lives in `apps/web/src/lib/seo/google-index-policy.ts`. `GOOGLE_INDEXABLE_PATHS` keeps exact paths for home, trust pages, authors, stats hubs and reports, tools, the wiki and codes indexes, and the existing top-10 codes pages. `/authors/<slug>` allows one profile slug without nested routes.
- `/catalog` and `/articles` allow every path beneath them, including path-based pagination. Prefixes match whole segments, so `/catalogue` stays denied. Query variants stay denied, and trailing slashes are normalized.
- `GOOGLE_INDEXABLE_GAMES` allows each listed game's wiki hub and every path beneath it, including future collections. It also allows that game's listed codes, quiz and checklist slugs. The games are restaurant-tycoon-3, blox-fruits, driving-empire, rivals, murder-mystery-2, fisch, lineage-piece, 1-speed-keyboard-escape, tower-of-hell, gakuran, animal-hospital, adopt-me, jujutsu-shenanigans, gym-star-simulator, ride-a-pet, steal-an-egg, forsaken, creatures-of-sonaria, brookhaven, evade, demonology and illegal-soccer. Brookhaven uses `brookhaven-rp` for its wiki and quiz. Both published Brookhaven codes slugs are included. Gym Star Simulator's wiki prefix is reserved for future pages; its hub currently returns 404. Per-game `/stats/games/<slug>` pages stay denied.
- To add a game, add one typed entry to `GOOGLE_INDEXABLE_GAMES` with its wiki slug and confirmed codes, quiz and checklist slugs. Use empty lists for page types without published pages. Other approved exact paths belong in `GOOGLE_INDEXABLE_PATHS`. An entry only lifts the Google restriction; it never overrides a page's own all-engine noindex.
- The proxy adds `X-Robots-Tag: googlebot: noindex, follow` to every HTML path that isn't allowlisted, including query variants. The header depends only on the URL, never on the user agent. APIs, `_next`, sitemaps, feeds, robots.txt, ads.txt and asset files are skipped.
- For metadata, don't set `googleBot: { index: true }` in page metadata. The root layout keeps only Google preview settings, so a page's meta tags never contradict the header.
- Nothing in this policy changes what Bing or other engines see. Generic robots meta, canonicals, content, dates and sitemaps stay the same, and sitemaps still list Google-noindexed pages.

## Analytics

- Public runtime loads the GA measurement ID and Umami website ID through separate client-visible variables because they identify different analytics systems. Workstation GA configuration belongs to shared application env; production values are injected by GitHub/Dokploy.
- GA4, Search Console, Bing, and Google OAuth operator values live in `.envs/operations/analytics.env`.
- Self-hosted Umami operator credentials and `UMAMI_WEBSITE_ID` live only in `.envs/operations/umami.env` and load through the `umami` overlay. The operator website ID matched the live production tracker ID during the 2026-08-14 read-only check.
- Reports and notebooks remain dated artifacts under `docs/analytics/reports`; they are analyses, not architecture authority.

## Distribution

`scripts/posts/` can publish updates to Telegram, X/Twitter, LinkedIn, and optional Facebook/Bluesky/Threads integrations. Credentials live in `.envs/integrations/distribution.env` or execution-platform secrets.

Social posting must not be coupled to database publication success in a way that prevents revalidation or leaves the content transaction ambiguous. Automation summaries use separate Telegram report secrets in GitHub Actions.
