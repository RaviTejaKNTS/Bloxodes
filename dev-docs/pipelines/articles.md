The standard targets US readers with American English and verified Eastern/Pacific event times. It uses contextual introductions, game/system-and-search-intent H2s, shorter contextual H3s, conversational follow-through, useful table interpretation, and natural endings. Highlights are optional rather than the default. Neither heading counts nor paragraph sentence counts impose a ceiling on useful explanation; humor is optional. Research confidence and access limitations stay in briefs; public status wording is concise and specific. Summary-to-detail repetition and useful developer attribution are allowed. Internal links and FAQs have no quota.

Review the reader promise, heading map, grouping, practical completeness, evidence, and localization before import. Mechanical JSON/media/browser validation supplements that judgment. The public-copy checker permits brief article/guide/page orientation for article-shaped finals while preserving stricter catalog and other page-family checks. A focused automated factual refresh applies the standard to changed copy without expanding into an unsolicited whole-article rewrite.

Approved-brief writing now uses a reader-facing packet before private evidence notes: goal, supported facts in task order, prerequisite/resource completeness, actionable uncertainties, and selected transformation examples. Community sourcing alone does not require repeated public caveats; actual conflicts and approximations remain explicit. The writer stage reads the relevant original before/after examples alongside the approved packet.

## Stages and ownership

1. Existing discovery and Groq curation gather and approve source-backed topics in managed development.
2. `run-homelab-article-batch.ts` acquires the shared article/wiki lock before queue recovery or mutation, selects exact curated IDs, and processes rows sequentially within the outer deadline.
3. `article-pipeline-queue.ts` claims each pending row with status/attempt compare-and-set. Code owns the lease and terminal queue update; model tasks do not receive database or release credentials through their environment.
4. `article-pipeline.ts` persists stage, attempts, revision budgets, feedback, input hashes and history. It runs research → research_review → images → image_review → image_upload → writing → editorial_review → copy_check → image_check → import_verify → browser_verify.
5. `article-stage-runtime.ts` runs focused Codex processes with native multi-agent features and apps disabled. It validates structured results and artifact ownership; review sessions use a read-only sandbox. Grok fallback uses `--no-subagents`. These controls prevent native worker management; the ordinary CLI filesystem/shell sandbox is not an adversarial isolation boundary for every operation a shell could perform.
6. Code uploads reviewed media with the existing collector, runs public-copy and image-readiness checks, imports into managed development and verifies row/provenance/route readback, then runs real headless Chrome QA. Neither an existing final file nor a model's completed message is enough to complete a queue row.
7. Only IDs returned completed by this code pipeline and read back completed under the selected batch are eligible for the existing controlled automatic production release. Existing scheduled publication policy is preserved; manual/test commands use managed development only unless release is separately authorized.
8. Existing production revalidation refreshes articles, feeds, sitemaps, related content and cache tags.

## Commands and recovery

- `npm run articles:writer:batch` is a read-only dry run. `--apply --limit <n>` processes curated rows; `--queue-id <uuid>` restricts selection. `--skip-production-release` retains accepted articles for human review.
- `articles:writer:local` and `articles:writer:homelab` are one-row compatibility entrypoints to this same controller, with production release disabled.
- `npm run articles:pipeline -- --input <job.json> --run-dir <repo>/tmp/article-pipeline/<run-id>` plans one explicit job; add `--apply` to execute. Job fields are id, title, slug, article_type, sources and optional refresh. This command never claims queue rows or publishes production content.
- Stable per-job run files live under `tmp/article-pipeline/<queue-id>/`: input.json, state.json, research_review.json, image_review.json, editorial_review.json, attempts/<stage>-<attempt>/ logs/prompts/decisions, and content/{brief.md,media.json,final.json,editorial-review.md}.
- For an explicitly repaired technical failure, the manual command accepts `--retry-technical` to retry before backoff expires. It consumes the existing operational recovery allowance and cannot override provider/editorial blockers or reset review counts. Never manually edit state counters.
- An interrupted running stage resumes from its saved artifacts after its process lease is released; completed stages do not rerun. Input or externally edited artifact changes cannot inherit cached approval. Review counters survive restart. Use a new run directory for an explicitly authorized fresh experiment; do not manually clear counters inside an active run.
- Evidence/editorial exhaustion uses blocked with no next_attempt_at: it needs attention instead of automatic repetition. Retryable provider/operational failures save retryAfter and resume the same stage after 180 minutes, with at most two later operational resumptions and the existing queue attempt limit. During backoff no worker launches. Provider access failure stops the remaining batch; untouched topics remain pending. Exceptions outside a recorded stage and interrupted claims retain bounded queue recovery. Failure reasons distinguish stage deadline, process/provider failure and editorial/evidence issues.
- `ARTICLE_PIPELINE_STAGE_TIMEOUT_MINUTES` defaults to 45; the existing outer batch deadline remains 300 minutes by default. Individual waits/file timestamps never cancel workers. Runtime shutdown terminates owned process groups and retains stage state.
- `ARTICLE_PIPELINE_PREVIEW_BASE_URL` can point to an existing managed-dev localhost/Tailscale preview. Otherwise code starts an owned Next preview on `ARTICLE_PIPELINE_PREVIEW_PORT` (default 3100), binds 0.0.0.0 with separate `.next-article-pipeline` output, and stops it when the run ends. A stopped owned preview is not a durable user link. Use the existing managed-dev preview/release-review flow for later human review.

All approved articles require a separate nonzero image pass before writing, as defined by the article workflow skills and `scripts/content/check-article-image-readiness.ts`.

Opinionated Roblox game-list articles remain ordinary `articles` rows. The reusable `roblox-game-card` fenced block carries a stable universe ID, square game icon, Roblox URL, and optional Bloxodes stats URL; all recommendation detail stays in the surrounding Markdown prose. The repo-local best-games workflow is split into discovery, selection/order, per-game research, and writing skills so the candidate set is not capped at a hardcoded count.

## Worker and fallback boundaries

- Model stage environments contain only required user/tool paths, locale/network configuration, read-only inventory URL and stage markers. They force process-only env loading and receive no Supabase, queue, Groq, publication or unrelated integration credentials. Deterministic upload/import/verification commands receive explicitly managed-development credentials and NODE_ENV=development with BLOXODES_ENV_PROFILE=process-only. This preserves the importer’s existing production-mode guard without loading another env target. Real env/auth files must not be opened by model tasks.
- Codex uses ephemeral runs, JSONL logs, a JSON response schema and disabled native multi-agent features. Writable tasks retain automatic approval review; focused reviewers use read-only execution without escalation. No model parent is left waiting or deciding when to interrupt another model.
- A nonzero Codex process exit permits one stage-only Grok fallback only when actual provider error events classify an authentication, quota/rate-limit, unavailable-model or unavailable-provider failure. A web source's error, timeout, malformed artifact, browser failure or editorial rejection does not cause a model switch. The fallback uses the same inputs/ownership checks and cannot spawn subagents.
- Writers leave cover_image null for the existing edited-cover importer. The cover is metadata only, not duplicated in content_md. Existing cover generation, image provenance, forward-only production import and exact-ID publication safeguards remain in their owning scripts.
- Already-running old batches can drain using the retained legacy skill reference when they carry ARTICLE_WRITER_BATCH_CONTEXT without an assigned stage. New automated batches use code-owned stages. No units, timers or env values need installation for this entrypoint replacement; no existing job is interrupted by the implementation.
